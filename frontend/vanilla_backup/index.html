Platform Security & Policies ENFORCED
🔒 Environment Separation

Strict isolation enforced: live API credentials cannot access test endpoints, and test credentials cannot access production resources.

🛡️ Cryptographic Key Hashes

API keys are hashed with salted PBKDF2/SHA256. Raw secrets are shown only once upon generation or rotation and are never retained at rest.

⚡ Ingestion Rate Limiting

Default policy enforces 120 requests/minute per connected application via Redis sliding-window counters with fail-closed security.

🔐 Payload Encryption

Inbound and historical payloads are protected at rest with AES-256 MultiFernet envelope encryption with key-rotation audit support.

CAPABILITY STATUS: SCHEDULED FOR SEPARATE PHASE

Message Scheduling Engine

The existing SenderX core architecture is engineered for immediate, real-time message ingestion, asynchronous Celery task execution, and multi-tenant delivery tracking. Native time-delayed scheduling is documented as a backend architectural gap.

Proposed Implementation Specification (Phase 6 Task)
  • Target Schema: Support for scheduled_at ISO-8601 UTC timestamp in message payload.
  • Broker Dispatch: Celery Beat periodic scheduler / Redis sorted sets (ZADD by timestamp).
  • Lifecycle State: SCHEDULED status preceding QUEUED with worker pick-up.
  • Cancellation API: DELETE /api/v1/messages/<id>/schedule prior to queue transition.
